Open-source Python agent framework · Apache-2.0

Build an agent in plain Python. Grow it one readable diff at a time.

tulip is an open-source Python agent framework: typed tools, streamed events, memory, RAG, multi-agent shapes and any OpenAI-compatible provider. Tools that move money can wait for a named person first, under a policy that runs in your process.

01

Give it tools that do things. Stream every step as a typed event.

A tool is a typed Python function: its signature and docstring become the schema the model sees. agent.run() streams the run as typed events, so a UI, a log or a test can render each step.

ledger.txtREFUND A-1009 40.001 line

Where this stops

A schema carries names, types and descriptions — not your rules about when a call is reasonable. The model still chooses the arguments, and only the tools in tools= are offered to it.

What the model sees, and the code behind the tool

The model is offered this schema, built from the type hints and the docstring. Docstring Args: lines become per-argument descriptions.

02

Remember the conversation. A thread outlives the process.

Give the agent a checkpointer and each thread is saved, so the next process picks up where the last one stopped. Files on your laptop; Postgres, Redis, S3 and others when you deploy.

Where this stops

A checkpoint is written when a run pauses or ends; set checkpoint_every_n_iterations to also save every few steps. A step that a crash cuts off is not replayed.

Docs: memory and checkpoints Docs: persist a conversation

03

Hand a question to a helper agent. Its answer comes back as a tool result.

Any agent can be another agent’s tool. The helper runs its own model loop over its own tools, and the parent sees only what it returns — the same shape as any other tool call.

Where this stops

Each helper is another model loop you pay for. as_tool sends it a prompt and returns its final answer; it does not share the parent’s thread. Give helpers the tools that read, and keep the ones that change something on one path you can check.

04

Let it act, under your policy. A small refund goes through. A big one waits.

Wrap the tool with gate_tool. The model sees the same tool, but every call is weighed against your ControlPolicy — in your process, before the function runs. A held call waits for a named person.

  • Spend limits: add spend_limit_usd and a FileSpendLedger, and each call is checked against the spend already recorded, then refused before anyone is asked. Concurrent calls can overshoot it — meter a tool with tool_execution="sequential".

Where this stops

Only wrapped tools are checked, and the check weighs the Action you describe, so describe the cost truthfully. An approval covers the same call — tool and arguments — from any thread until it is used; bind it tighter with approval_context. Resume only after a decision: resuming a still-pending hold ends the run without making the refund.

Docs: gate a tool
What the policy checks

ControlPolicy() on its own holds every call that arrives without a VerificationResult — a separate check, for work that scores its own evidence. Nothing in this file produces one, so the refund policy sets require_verification_score=0 and the two limits below are all that weigh a call: the per-call amount, and, when you add a ledger, the running total. 05

Test it without a model. Scripted turns. No network, no key.

tulip.testing ships stand-in models: the test decides what the model says, and then checks what tulip did — which tools ran, in what order, with what answer. Turn the agent into a build() factory so a test can pass one in.

Where this stops

A scripted test proves your wiring, not the model’s judgement. EvalCase and EvalRunner check tool order and output across many cases; there is no hosted eval dashboard.

The rest of the framework

Plug in what you already run. Build bigger when a task needs it.

Each works with the same tools, events and checkpointers as the file above. All the guides

  • MCP servers docs

    MCPClient turns each tool an MCP server offers into an ordinary tulip tool. TulipMCPServer offers yours to other clients.

    limitA tool you attach straight to the agent is not wrapped, so nothing checks it.

  • Serve over HTTP docs

    AgentServer runs an agent behind bearer auth and server-sent events, with threads scoped per key. Without a key it only listens on localhost.

    limitA run that pauses for a person ends the stream; no HTTP route resumes it.

  • Any OpenAI-compatible provider docs

    One model string for a hosted endpoint or one on your own machine, and register_provider for a client you write yourself.

    limitNo automatic failover between providers.

  • Token streaming docs

    stream_tokens=True adds the model’s text, as it arrives, to the same typed event stream the rest of the run uses.

  • Workflow shapes docs

    SequentialPipeline, ParallelPipeline, LoopAgent, StateGraph, Handoff, Orchestrator and Swarm compose agents into a bigger run.

  • Your documents docs

    RAGRetriever over an in-memory store, pgvector, Qdrant and others; create_rag_tool makes it one tool the agent can call.

    limitYou bring the embedding model.

  • Grounded answers docs

    Scores a claim against typed Evidence. When the evidence does not support it, the result is an abstain Abstention instead of a guess.

  • Tracing docs

    An OpenTelemetry hook emits spans and metrics carrying tulip.* attributes, and an event bus carries lifecycle events to your own sinks.

    limitIts own attribute names, not the OpenTelemetry GenAI conventions.

What tulip does not do. Specific guarantees, with their edges.

The five worth knowing before you start.

LimitDo this instead

  1. It doesn’t run your agent for you.

    →Do this instead: No hosted runtime, no hosted eval dashboard. You deploy it, or run it from a terminal.

  2. It doesn’t fail over between providers.

    →Do this instead: One model string goes to one endpoint. Wrap it yourself, or give the agent a fallback path.

  3. It doesn’t replay a step a crash cut off.

    →Do this instead: A checkpoint is the last completed step. Make the tools you retry idempotent.

  4. It doesn’t check tools you haven’t wrapped.

    →Do this instead: Wrap every tool that can change something with gate_tool.

  5. It doesn’t make the model right, or stop prompt injection.

    →Do this instead: A hold stops an unapproved side effect on a gated tool, not the bad idea. What each control covers

# tulip

tulip is an open-source Python agent framework: typed tools, streamed events, memory,
RAG, multi-agent shapes and any OpenAI-compatible provider. When a tool would move money
or change a real system, a policy you write is checked in your own process before it runs.

## Install

    pip install tulip-agents            # enough for the offline version
    pip install "tulip-agents[llm]"     # to reach your own OpenAI-compatible endpoint

## The first agent

    from tulip import Agent, tool

    ORDERS = {"A-1009": "shipped, due Thursday"}


    @tool
    def order_status(order_id: str) -> str:
        """Where an order is right now."""
        return ORDERS[order_id]


    agent = Agent(
        model="openai-compatible:your-model",
        tools=[order_status],
    )

## Run it

    export TULIP_OPENAI_COMPATIBLE_BASE_URL=https://your-endpoint/v1
    tulip run agent.py:agent "Where is order A-1009?"

The CLI is `tulip run | resume | approvals | audit | serve`; `tulip <command> --help`
prints the flags.

## Watch the run as typed events

    import asyncio

    from tulip import TerminateEvent, ToolCompleteEvent, ToolStartEvent

    from agent import agent


    async def main():
        async for event in agent.run("Refund $40 on order A-1009"):
            match event:
                case ToolStartEvent(tool_name=name, arguments=args):
                    print("calling", name, args)
                case ToolCompleteEvent(result=result):
                    print("result ", result)
                case TerminateEvent(reason=reason):
                    print("stopped", reason)


    asyncio.run(main())

## Remember a thread across processes

    from tulip.memory.backends import FileCheckpointer

    agent = Agent(..., checkpointer=FileCheckpointer("checkpoints"))

## A helper agent as a tool

    helper = Agent(model=MODEL, tools=[return_window])
    agent = Agent(model=MODEL, tools=[order_status, helper.as_tool("returns", "Questions about returns.")])

## A policy in front of a tool that moves money

    from tulip.control import Action, AuditTrail, ControlPolicy, FileApprovals, gate_tool

    trail = AuditTrail()

    refund = gate_tool(
        issue_refund,
        policy=ControlPolicy(
            require_human_over_usd=500,    # over $500 waits for a person
            require_verification_score=0,  # nothing here produces a score
        ),
        action=lambda name, args: Action(
            name=name,
            asset=args["order_id"],
            kind="payment",
            cost_usd=args["amount_usd"],
        ),
        approval=FileApprovals("approvals.json"),
        on_refusal="interrupt",
        trail=trail,
    )

A bare ControlPolicy() holds every call that arrives without a VerificationResult, so a
policy that scores no verification sets require_verification_score=0. An approval covers
the same tool and arguments from any thread until it is used.

## Test it with no model

    from tulip.control import FileApprovals
    from tulip.testing import AgentTestClient, ScriptedModel, text, tool_call

    import agent
    from shop import payments

    SHIPPED = text("Order A-1009 is shipped, due Thursday.")


    def test_it_answers_from_its_tool():
        model = ScriptedModel([tool_call("order_status", order_id="A-1009"), SHIPPED])

        run = AgentTestClient(agent.build(model)).run("Where is order A-1009?")

        run.assert_tools_called("order_status")
        assert "Thursday" in run.message


    def test_a_big_refund_waits_for_a_person(monkeypatch, tmp_path):
        monkeypatch.chdir(tmp_path)
        paid = []
        monkeypatch.setattr(payments, "refund", lambda *a: paid.append(a) or "ok")
        call = tool_call("issue_refund", order_id="A-1009", amount_usd=4200)
        model = ScriptedModel([call, text("that refund is waiting")])

        AgentTestClient(agent.build(model)).run("Refund $4,200 on order A-1009")

        assert paid == []
        assert [p.tool for p in FileApprovals("approvals.json").pending()] == ["issue_refund"]
